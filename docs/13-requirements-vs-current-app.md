# 要件と既存アプリ（HypoFrame）の照合

依頼要件と現在の HypoFrame のフローを照らし合わせ、対応状況とギャップを整理する。

---

## 1. 既存アプリ（HypoFrame）のフロー概要

### 1.1 技術スタック・形態

| 項目 | 現状 |
|------|------|
| 実装言語 | **TypeScript / Next.js**（フロント + API Route） |
| 形態 | **Web アプリ（UI あり）**。ブラウザで操作。 |
| 生成 AI | Groq API（LLM） |
| データ保存 | Supabase（PostgreSQL）。認証・runs テーブル。 |
| クロール | Node.js（fetch + cheerio）。同一ドメイン内・最大8ページ・深度2・robots.txt 尊重。 |

### 1.2 現状の処理フロー

**単一 URL 入力**
```
[ユーザー] 企業HPのURL + 会社名（任意）を入力
    ↓
[Page Collector] 同一ドメインから最大8ページを取得（URL優先スコア・深度2）。HP内 PDF は取得・テキスト抽出（pdf-parse）
    ↓
[Structurizer] HTML → 本文抽出・カテゴリ別整理（解釈なし）
    ↓
[Hypothesis Engine] 要約 → 仮説5段 → 提案文下書き（Groq 3回呼び出し）。代表者名・IR要約を含む
    ↓
[出力] 画面上に表示。ログイン時は DB に保存。.txt / CSV / コピー。Google Sheet・Docs 出力（OAuth 連携時）。
```

**リストからの複数 URL**
```
[ユーザー] 検索クエリ（業界・地域・キーワード）で「企業を検索」→ 候補一覧から最大3件選択 → 「選択した企業で生成」
    ↓
[各候補] 上記「単一 URL 入力」と同様のフローを順次実行（件間4秒待機で Groq TPM 考慮）
    ↓
[出力] 候補ごとに結果表示。「一覧をCSVでダウンロード」で一括 CSV。各結果から Sheet/Docs 出力も可能。
```

### 1.3 入力

| 項目 | 現状 |
|------|------|
| 企業リストの取得 | ✅ **企業を検索してリスト化**。Google Custom Search API で検索し、候補（タイトル・URL・スニペット）を一覧表示。従来の **1件ずつ URL 手入力**も利用可能。 |
| Google 検索 | ✅ `GET /api/search?q={クエリ}`。Custom Search API 利用（専用 GCP プロジェクトでの API キー推奨）。 |
| 業界・地域などの条件検索 | ✅ 検索クエリに業界・地域・キーワードを含めて指定。同時選択は **最大3件**、件間4秒待機で Groq TPM を考慮。 |

### 1.4 情報取得（企業HP＋周辺）

| 項目 | 現状 |
|------|------|
| 企業公式 HP | ✅ 同一ドメイン内をクロール（最大8ページ）。 |
| HP 内 IR 情報 PDF | ✅ HP 内 PDF リンクを検出・取得し、pdf-parse（PDFParse）でテキスト抽出。要約に IR 要約を反映。 |
| Google 上の企業情報（概要・ニュース等） | ✅ 企業名（または URL ホスト名）で検索し、スニペット最大2件を要約の補助入力に付与。 |
| 動画の読み込み / 動画 URL 抽出 | **未対応**。 |

### 1.5 LLM による要約・仮説生成

| 項目 | 現状 |
|------|------|
| 事業内容の要約 | ✅ あり（summaryBusiness）。業種・従業員規模も抽出。 |
| IR 内容（PDF）の要約 | ✅ PDF テキストを取得し irSummary として要約・出力。 |
| その他企業情報の要約 | ✅ HP 内テキスト ＋ IR PDF ＋ Google 検索スニペット（最大2件）を要約。 |
| 代表者名（代表者/役員等） | ✅ 要約から decisionMakerName を抽出・出力。 |
| 「課題仮説 → 提案」形式の手紙下書き | ✅ 仮説5段 + 提案文下書き（letterDraft）。 |
| 断定を避けた仮説表現 | ✅ プロンプトで「断定を避ける」指示あり。 |

### 1.6 出力

| 項目 | 現状 |
|------|------|
| Google スプレッドシート | ✅ OAuth 連携後、結果を新規スプレッドシートに出力（企業名/URL/要約/仮説/代表者名/手紙等）。 |
| Google ドキュメント | ✅ 手紙下書きのみ新規ドキュメント作成。 |
| CSV | ✅ 単体結果の CSV ダウンロード。リストから生成した複数件は「一覧をCSVでダウンロード」で一括出力。 |
| アプリ内表示 | ✅ 要約・仮説5段・提案文を表示。 |
| ファイル出力 | ✅ .txt エクスポート（UTF-8）。コピー対応。 |
| DB 保存 | ✅ ログインユーザーごとに runs テーブルに保存。 |

## 2. 依頼要件の整理（業務範囲）

### ① リスト作成（Google検索 → 企業HP抽出）

- 指定条件（業界・地域など）で Google 検索。
- 検索結果から企業名・企業HP URL を抽出。
- 出力先：Google スプレッドシート または CSV。
- Google の仕様・規約に配慮（API 利用案も歓迎）。

### ② 企業情報取得（企業HP＋周辺情報）

- 企業公式 HP。
- HP 内 IR 情報 PDF など。
- Google 上の企業情報（概要・ニュース等）。
- （可能なら）動画も読み込み、難しければ動画 URL 抽出まで。

### ③ LLM による要約・仮説生成

- 事業内容の要約。
- IR 内容（PDF）の要約。
- その他企業情報の要約。
- 代表者名（分かれば：代表者/役員等）。
- 「課題仮説 → 提案」形式の手紙下書き生成。

### ④ 出力（必須）

- Google スプレッドシートに  
  **企業名 / URL / 要約 / 仮説 / 代表者名（任意）/ 手紙下書き** を整形して出力。
- 手紙下書きは Google ドキュメント出力も可（運用しやすい形で提案）。

### その他

- **成果物**: Python スクリプト一式・設定ファイル・出力フォーマット・簡易マニュアル。
- **技術要件**: Python、生成 AI API、Web 情報取得、PDF 取得・テキスト抽出・要約、Google スプレッドシート/Docs への書き込み。
- **歓迎**: Playwright/Selenium、LlamaIndex/LangChain、エラー耐性（リトライ・ログ・例外処理）。
- **注意**: UI/アプリ開発は不要（管理画面なし）。生成文は仮説として。自動送信は行わない。スクレイピングは規約・robots 等に配慮。

## 4. まとめ：ギャップと位置づけ

### 4.1 既存アプリでカバーできている部分

- **企業 HP のクロール**（同一ドメイン・規約配慮・構造化）
- **HP 内 IR PDF の取得・テキスト抽出・要約への反映**
- **HP テキスト ＋ IR の要約 → 仮説5段 → 提案文下書き**（断定を避けた表現・代表者名抽出）
- **リスト作成**（Custom Search で検索→候補選択、最大3件同時・件間4秒で順次生成→一括 CSV）
- **出力**：.txt / CSV（単体・一覧）/ Google スプレッドシート / Google ドキュメント（手紙）/ コピー
- **アプリ内での編集・保存・履歴**

### 4.2 要件に対して不足している主な点

1. **情報源の拡張**  
   動画（または動画 URL）は未対応。HP ＋ IR PDF ＋ Google 上の企業情報（検索スニペット）は対応済み。
2. **形態**  
   要件は「Python・UI なし」、現状は「Next.js・Web UI あり」。

### 4.3 位置づけの整理

- **依頼要件**: 「リスト作成 → 企業情報取得 → 要約・仮説・手紙 → **スプレッドシート/ドキュメント出力**」までを **Python スクリプト（UI なし）** で一気に実行するバッチ的な成果物。
- **HypoFrame（現状）**: **検索で企業候補を取得**し、**最大3件を選択**して順次仮説生成。**1 URL 入力**も利用可能。**HP ＋ IR PDF** を元に要約・仮説・手紙を生成し、**画面表示・CSV・Google Sheet/Docs・DB** で完結する **Web アプリ**。

そのため、

- **MVP のコア**（「Google→企業URL抽出 → HP/IR取得 → 要約 → 手紙下書き → スプレッドシート出力」）のうち、  
  HypoFrame でカバーしているのは **リスト作成・HP/IR 取得・要約・代表者名・手紙下書き・Sheet/Docs/CSV 出力** まで。
- **未対応**は **動画（URL）** および **Python 化・UI なし** の形態差。

## 5. 今後の検討の例（要件にさらに近づける場合）

すでに実装済み：リスト作成（Custom Search・最大3件選択・件間待機）、PDF（IR）（pdf-parse）、代表者名、出力先（CSV・Sheet・Docs）、**Google 上の企業情報**（企業名/ホスト名で検索→スニペット最大2件を要約補助に付与）。  
以下は追加で検討する場合の例（実装可否・優先度は別途判断）。

| 検討項目 | 内容 |
|----------|------|
| Google 上の企業情報 | ✅ 実装済み（Serper 検索でスニペットを要約の補助に利用）。 |
| 動画 URL 抽出 | HP 内の YouTube 等リンクを抽出し、結果・CSV/Sheet に列追加。 |
| リストの同時選択数・待機時間 | 現状は最大3件・件間4秒。Groq の Tier 変更やキュー導入で増やす検討も可。 |
| Python 版 | 既存の「クロール→構造化→要約→仮説→手紙」ロジックを Python に移植し、API やバッチとして実行。UI は持たない。 |

上記は「要件との照合」に基づく検討リストであり、実装順序・採用可否は別ドキュメントまたは仕様で決定する。
